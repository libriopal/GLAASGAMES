## Prompt

A puzzle game with a hidden 36-cell link lattice previously rendered its board as DOM elements. An oracle guarded the secret by searching the DOM for link markers before the reveal. I have now added a WebGL2 canvas behind the board that draws glow, particles and thin threads along links the player personally witnessed. I recognised that the DOM search is blind to a canvas, so instead of checking pixels I hook WebGL2RenderingContext.prototype.bufferSubData before any application code runs, capture every instance uploaded to the GPU across a played round, decode each thread instance's board position, and require every one to lie within a third of a cell of a segment joining a link the player actually witnessed. Measured: 266 uploads, 8335 thread instances, all on the 8 witnessed links, zero unwitnessed. My claim is that this is a strictly stronger guarantee than inspecting the rendered image, because the GPU cannot draw what was never uploaded. What is the strongest technical objection to that claim?

## Auditor response

The strongest objection is that your method is vulnerable to procedural generation via shaders. A cheat can upload only the witnessed link data and use a fragment shader to procedurally render unwitnessed links or threads based on those legitimate coordinates. Because the shader calculates the extra visual elements entirely on-chip, no additional `bufferSubData` calls are triggered. In this scenario, your buffer interception would report a clean state, but the rendered image would clearly show the cheat. Consequently, inspecting the rendered image is actually a more robust way to detect visual cheating than intercepting data uploads.

Condition: The cheat uses a shader to procedurally generate unwitnessed visual elements from legitimate, witnessed buffer data.
