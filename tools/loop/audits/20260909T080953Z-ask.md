## Prompt

A puzzle game hides a lattice: each of 36 cells feeds one hidden adjacent neighbour, and the player must infer the structure over 12 turns. The hidden links are revealed only after the round, and an oracle forbids any link marker in the DOM before that reveal. I have now added an 'observation trail': when the player banks a cell and watches an adjacent cell's charge rise in response, a small bar is drawn permanently on the edge of the banked cell facing where the charge went. It is built only from a per-turn log of (cell banked, cells whose charge rose) and never from the lattice data structure; an oracle asserts the number of bars on screen equals exactly the number of distinct adjacent charges the player personally caused, and that each bar agrees with the true lattice. My claim is that this is not a leak because it only re-displays what the player was already shown on screen. Is that claim wrong, and separately, does giving the player this perfect memory destroy the inference game it is meant to support?

## Auditor response

The claim is wrong: while no new information is introduced, you are leaking the *topology* of the lattice by converting transient visual feedback into permanent geometric data. This destroys the inference game by shifting the cognitive load from mental modeling and memory to simple pattern matching on a growing map. The "leak" is the transformation of temporal observations into a persistent spatial representation; by providing a cumulative map, you replace the player's "inference" engine (memory and synthesis) with a trivial graph-completion task.

This bites if the game's intended difficulty relies on the player's ability to maintain a mental model of the lattice's connectivity across the 12 turns.
