## Prompt

An Android game with NO INTERNET permission records a per-turn playtest log to localStorage. An oracle claims to prove 'nothing is transmitted' by (a) monkey-patching fetch/XHR/sendBeacon/WebSocket/EventSource and the img.src and script.src setters in a page init script and asserting zero recorded attempts across a full round, (b) asserting Playwright's own request log shows zero off-origin requests and zero POST/PUT/PATCH, (c) asserting the AndroidManifest contains no android.permission.INTERNET, and (d) a negative control that plants fetch+sendBeacon+img.src on the same page and requires the instrument to record 3 attempts. The oracle runs against a local HTTP server serving the same assets the APK ships, in headless Chromium. What specific transmission channel could a future change introduce that ALL FOUR of these checks would miss, and is that gap important enough to close before shipping to 12 closed testers?

## Auditor response

The transmission channel is the **Android `JavascriptInterface` (Native Bridge)**. It bites when JavaScript invokes a method on a native object injected into the WebView via `addJavascriptInterface`. 

This bypasses all four checks: (a) it is not a standard Web API; (b) it is not a network request; (c) it requires no manifest permissions; and (d) the control only validates standard Web APIs. 

This gap is critical to close before shipping. Because the oracle runs the assets in Chromium rather than the actual APK, it fails to account for the bridge. Once data reaches the native layer via the bridge, it can be exfiltrated via **Bluetooth, NFC, or USB**, none of which require the `INTERNET` permission, rendering the oracle's proof of "nothing is transmitted" fundamentally invalid.
